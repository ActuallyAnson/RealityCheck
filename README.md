# RealityCheck

**An adversarial tester for simulations.** A model hunts for scenarios where a simulation breaks its own declared rules.
A deterministic engine, not the model, decides what counts as a violation. Each failure is shrunk to a minimal
scenario, replayed, explained with cited steps that are checked against the recording, and exported as a regression
test. Built solo for the Meta Global AI Developer Hackathon (Indie Developer track, "Push the Frontier") on the
Meta Model API (Muse Spark).

Simulations fail silently: a robot controller that exceeds its force limit once in a million runs, an integrator that
drifts only with five bodies and a coarse step. Nobody writes that test. RealityCheck lets a model propose the
nasty scenario, and lets a plain program prove or disprove it.

## How it works

```
        model (Muse Spark, tool calls, vision)             deterministic, no model
  ┌───────────────────────────────────────────┐   ┌──────────────────────────────────────┐
  │ hypothesis ─► run_scenario ─► inspect ─►  │──►│ simulator ─► declared rules checked  │
  │ shrink ─► counterfactual ─► submit_report │◄──│ at every step ─► violation or not    │
  └───────────────────────────────────────────┘   └──────────────────────────────────────┘
        report accepted only if every cited step/value matches the recorded run,
        and (v2) a one-change counterfactual that removes the failure really passes
```

- **The model never decides pass or fail.** Rules are declared per domain and checked by code.
- **No ground truth in the prompt.** Seeded bugs are hidden behind a mask only the simulator reads; the evaluation
  harness reads the answer key, the tester never does (tests check the prompts for leaks).
- **Reports are grounded.** A report is rejected if it cites a step, body or value that does not exist, or, in agent v2,
  if its counterfactual still fails, is not a one-change variant, or is too short to show the failure.
- **Cost is capped on three levels:** per run, per evaluation, and a lifetime ledger outside the repo.

## What is in the box

| Piece | What it does |
|---|---|
| Three domains | rigid-body physics (13 seeded bugs), orbits (3), cart-pole control (3), same tools, rules, shrinker and agent |
| Outside engines | unmodified Box2D 3.x tested through the same rules (`docs/EXTERNAL_ENGINE.md`) |
| Bring your own simulator | any program speaking a JSON-lines pipe protocol (`docs/PROTOCOL.md`) |
| Differential testing | `rc_diff` compares two engines with no rules (an independent orbit integrator agrees with the built-in one at a fine step and disagrees at a coarse step) |
| Regression tests | `rc_repro` turns a failure into `scenario.json` + `test.sh` (exit code and JUnit output for CI) |
| Agent v1 and v2 | v2 adds a checked counterfactual and frames shown in the loop; v1 stays frozen for comparison |
| Viewer | dark web UI: pipeline stepper, original/shrunk playback, evidence with checked citations, scoreboard, WebAudio sound, live runs against the real API |
| Evaluation | locked evaluation sets, random baseline, controls on the clean simulator, Wilson intervals, ablation arms |

## Results

All numbers are generated by scripts from files in this repo: `scripts/gen_results.sh` writes `docs/RESULTS.md`.
Headline, read together with the caveats below:

- Agent v1 and v2 reliably find and shrink bugs and produce grounded reports in all three domains, with
  the cost per run around $0.05 to $0.09.
- Against random testing the advantage is **mixed**: the agent wins on needle bugs (conditions random sampling rarely
  hits) and ties or loses where the condition is common. The ablation on fresh held-out bugs is in `docs/RESULTS.md`.
- Where the agent is wrong matters as much: the explanation is a hypothesis. A hand audit of the keyword scorer
  found it overstates correct causes (`docs/SCORER_AUDIT.md`), which is why v2 scores cause by counterfactual.

## Caveats (read these)

- Seeded bugs were planted by the author; they are controlled test cases, not discoveries. The only claims about real
  engines are in `docs/EXTERNAL_ENGINE.md` and they are modest: Box2D shows soft-contact penetration and, with
  continuous collision off, tunneling; no new Box2D bug is claimed.
- Controls (a clean simulator, no bug) have repeatedly caught weaknesses in my own simulators: the rigid-body
  simulator v1 (fixed in v2, and a related heavy-light squeeze is still found by agents), and the cart-pole scenario
  envelope (three attempts, `docs/CARTPOLE_DOMAIN.md`). These are reported, not hidden.
- Sample sizes are small (5 to 10 seeds per bug). Seeds label independent, nondeterministic runs; the model is not seeded.
- Attribution ("the failure is due to the seeded bug") is checked post hoc by replaying on the clean simulator.
- The wall-clock budget of the random baseline is not applied to the agent; the step budgets are identical.
- Differential testing works when two engines are numerically close; for contact dynamics it mostly reports chaos.
- Agent explanations can read telemetry the tools return (for example substep counts), so "names cause" partly measures
  reading that telemetry.

## Build and run

    cmake -S . -B build && cmake --build build -j && ./build/rc_tests

Optional, for the Box2D engine: `brew install box2d` before configuring. Everything else is plain C++17, no
third-party dependencies, no network unless `--live` is passed.

    ./build/rc_demo --open                          # viewer at http://127.0.0.1:8080 (recorded runs; Live needs MODEL_API_KEY)
    ./build/rc_hunt --engine builtin:o02 --domain orbit --scenarios 400 --bundles out/    # random hunt + regression bundles
    ./build/rc_diff --a builtin --b 'exec:./build/naive_orbit 0.03' --domain orbit --tol 0.1 --horizon 1
    ./build/rc_repro check --repro out/orbit_momentum_conserved --engine builtin:o02       # exit 1: failure reproduces
    ./build/rc_agent --live --domain orbit --bugs o02 --agent-version 2 --out runs/x       # needs MODEL_API_KEY

The API key lives in your environment (`MODEL_API_KEY`), never in the repo. The model client shells out to `curl`.

## Repo map

`src/sim` simulators and scenarios, `src/rules` declared rules, `src/tools` the six deterministic tools,
`src/shrink` shrinker, `src/agent` the tester agent, `src/model` API client + replay/record/mock backends and budgets,
`src/external` engine adapters, protocol, hunt/repro/diff tools, `src/eval` evaluation harness, `src/viewer` +
`src/demo` + `web` the viewer, `data` hidden ground truth and locked evaluation sets (harness only), `results`
generated outputs, `docs` write-ups. `WHAT_WE_BUILT.md` lists what was created during the hackathon.
