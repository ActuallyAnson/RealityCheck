# RealityCheck

**A verification harness for simulations, where a model proposes and a program decides.** A model hunts for scenarios in which a
simulation breaks its own declared rules and explains the ones it finds. A deterministic engine, not the model, decides what counts
as a violation, shrinks each failure to a minimal scenario, checks every cited step and value against the recording, and exports a
regression test. Built solo for the Meta Global AI Developer Hackathon (Indie Developer track, "Push the Frontier") on the Meta
Model API (Muse Spark).

Simulations fail silently: a robot controller that exceeds its force limit once in a million runs, an integrator that drifts only
with five bodies and a coarse step. Nobody writes that test. The design rule here is simple: **the model never gets to be the
judge**. It proposes; code verifies; and every claim in this README is backed by a locked evaluation, with the negative results kept.

```
        model (Muse Spark, tool calls, vision)             deterministic, no model
  ┌───────────────────────────────────────────┐   ┌──────────────────────────────────────┐
  │ hypothesis ─► run_scenario ─► inspect ─►  │──►│ simulator ─► declared rules checked  │
  │ shrink ─► counterfactual ─► submit_report │◄──│ at every step ─► violation or not    │
  └───────────────────────────────────────────┘   └──────────────────────────────────────┘
        report accepted only if every cited step/value matches the recorded run,
        and (v2) a one-change counterfactual that removes the failure really passes
```

## What the evidence says

All numbers are generated by scripts from files in this repository (`scripts/gen_results.sh` writes `docs/RESULTS.md`).
Seeded bugs are planted by me; see the caveats before reading anything as "the model finds bugs".

| Question | Answer | Where |
|---|---|---|
| Given a failure, does the model find the cause better than a program? | **Yes.** On 83 failures found by random testing, the agent localized the cause in 52 (63%) against 35 (42%) for a no-model localizer; paired sign test p = 0.006. 81 of 83 reports passed the engine's checks. | `docs/TRIAGE.md` |
| Does the model find failures better than random testing? | **Not in general.** It helps on a few rare-condition bugs, ties on common ones, and loses on the traffic domain (t02 1/5, t03 3/5 against 5/5 for random). | `docs/RESULTS.md`, `docs/TRAFFIC_DOMAIN.md` |
| Does a smarter search (margin-guided hill climbing) beat random? | **No.** Tested with no model at equal step budget; it found each bug no more often than random in all 15 rows. So guided search was not built into the agent. | `docs/GUIDED_SEARCH.md` |
| Can a model write the rules from a description? | **Partly.** Model-written invariants hit 9 of 22 seeded bugs against 19 of 22 for hand-written rules; they find conservation laws but write loose bounds. A second attempt with duration forms hit 0 of 3 on traffic. | `docs/SPEC_RULES.md` |
| Is the v2 agent (checked counterfactual, frames in the loop) better than v1? | **Not clearly.** 20/30 against 19/30 valid and attributable, overlapping intervals; cause localization is better with frames (20/30 against 15/30). | `docs/RESULTS.md` |
| Does it work on code I did not write? | **Yes, as a harness.** Unmodified Box2D 3.x and REBOUND 5.2.2 run through the same rules and a 14-scenario literature corpus (all pass). That run also surfaced a reproducible hang in REBOUND's default IAS15 mode on the figure-eight initial condition (not reported upstream; not claimed as a confirmed bug). | `docs/EXTERNAL_ENGINE.md` |
| Does it flag clean simulators? | Controls repeatedly caught weaknesses in my own simulators (rigid-body v1, the cart-pole scenario envelope); all are reported. | `docs/CARTPOLE_DOMAIN.md` |

Costs: about $0.04 to $0.09 per agent run; about $20 of API spend in total, capped per run, per evaluation, and by a lifetime ledger.

## What is in the box

| Piece | What it does |
|---|---|
| Four domains | rigid-body physics (13 seeded bugs), orbits (3), cart-pole control (3), a traffic-signal state machine (3); same tools, rules, shrinker and agent |
| Tester agent | v1 (frozen) and v2 (counterfactual-checked reports, frames in the loop); a triage mode that explains a failure found by a fuzzer |
| Deterministic tools | `run_scenario`, `check_rules`, `inspect_state`, `render_frames`, `shrink`, `replay`; also as a local HTTP API and an MCP server, no model needed (`docs/API.md`) |
| Spec to rules | the model proposes invariants from a description; the engine keeps those that hold on clean runs (`docs/SPEC_RULES.md`) |
| Outside engines | unmodified Box2D and REBOUND, plus any program speaking the JSON-lines protocol, with a per-request deadline (`docs/PROTOCOL.md`) |
| Differential testing, regression tests | `rc_diff` compares two engines; `rc_repro` turns a failure into `scenario.json` + `test.sh` with JUnit output; a GitHub Action re-runs bundles on pull requests |
| Viewer and reports | dark web UI with pipeline stepper, playback and checked citations, live runs against the real API, and a single-file offline report per finding (`scripts/share_report.sh`) |
| Evaluation | locked sets, random baseline, controls, Wilson intervals, paired tests, an ablation, an external scenario corpus (`data/external_scenarios/`), CI on Linux and macOS |

## Caveats (read these)

- Seeded bugs were planted by the author; they are controlled test cases, not discoveries. The only claims about real software are in
  `docs/EXTERNAL_ENGINE.md` and they are modest: Box2D shows soft-contact penetration and, with continuous collision off, tunneling; REBOUND's
  fixed-step integrators drift at coarse steps as expected; one hang in a default mode is reproduced but not confirmed as a defect.
- Every bug in the triage and spec evaluations had been seen in earlier work, so none of those is fresh held-out.
- Sample sizes are small (5 to 10 seeds per bug). Seeds label independent, nondeterministic runs; the model is not seeded.
- "Localized" in the triage evaluation means the counterfactual changed a hidden trigger field. It does not grade the written explanation, and a
  hand audit found the older keyword scorer overstates (`docs/SCORER_AUDIT.md`).
- Controls on a clean simulator are mostly clean; the exception (rigid-body heavy-light squeeze, 2 of 9 control runs in the ablation) is in `docs/RESULTS.md`.
- Attribution ("the failure is due to the seeded bug") is checked post hoc by replaying on the clean simulator.
- Determinism is per platform: a run is bit-for-bit reproducible on the same machine type, but libm differences change simulated traces on Linux compared
  with macOS. CI found this; pinned trace hashes are checked on macOS only, and I have not re-run the evaluations on Linux.
- Differential testing works when two engines are numerically close; for contact dynamics it mostly reports chaos.
- The wall-clock budget of the random baseline is not applied to the agent; the step budgets are identical.

## Build and run

    cmake -S . -B build && cmake --build build -j && ./build/rc_tests

Optional, for the Box2D engine: `brew install box2d` before configuring. Everything else is plain C++17, no third-party dependencies, no network
unless `--live` is passed. CI builds and tests on Ubuntu and macOS.

    ./build/rc_demo --open                          # viewer at http://127.0.0.1:8080 (recorded runs; Live needs MODEL_API_KEY)
    ./build/rc_hunt --engine builtin:o02 --domain orbit --scenarios 400 --bundles out/    # random hunt + regression bundles
    ./build/rc_diff --a builtin --b 'exec:./build/naive_orbit 0.03' --domain orbit --tol 0.1 --horizon 1
    ./build/rc_repro check --repro out/orbit_momentum_conserved --engine builtin:o02       # exit 1: failure reproduces
    ./build/rc_agent --live --domain orbit --bugs o02 --agent-version 2 --out runs/x       # needs MODEL_API_KEY
    ./build/rc_api_server --mcp                     # the deterministic tools as an MCP server (no key)
    ./build/rc_corpus                               # run the 14 externally sourced scenarios

The API key lives in your environment (`MODEL_API_KEY`), never in the repo. The model client shells out to `curl`.

## Repo map

`src/sim` simulators and scenarios, `src/rules` declared rules and margins, `src/tools` the six deterministic tools, `src/shrink` shrinker,
`src/agent` the tester agent, `src/model` API client, replay/record/mock backends and budgets, `src/external` engine adapters, protocol,
hunt/repro/diff tools, `src/spec` spec-to-rules, `src/api` the API/MCP server and corpus runner, `src/eval` evaluation harness,
`src/viewer` + `src/demo` + `web` the viewer, `data` hidden ground truth, locked evaluation sets and external scenarios (harness only), `results`
generated outputs, `docs` write-ups, `examples/external` sample simulators and adapters. `WHAT_WE_BUILT.md` lists what was created during the hackathon.
