## 2. Tier 1: must ship (this is the demo)
- **Viewer** (vanilla JS + canvas, no build step):
  - left: live feed of the agent's hypotheses and tool calls as cards with latency and cost chips;
  - centre: arena canvas with trails, timeline scrubber with violation markers, energy plot;
  - right: evidence panel; rule, cited steps (click a citation to jump the canvas to that step and highlight the body),
    frame strip, vision note with an agrees/disagrees badge;
  - original and shrunk scenario replayed side by side;
  - top bar: model name, LIVE or RECORDED badge, spend meter against the cap;
  - scoreboard view: agent vs random baseline per bug, held-out marked, misses shown, not hidden.
- **C++ server** (`rc_demo`): static files plus Server-Sent Events that stream `events.jsonl` as the agent runs.
  One command builds and runs; opens the browser. **Recorded fallback** replays a saved run through the same event
  path and is always labelled RECORDED.
- **README** with an architecture diagram, results tables generated by `rc_eval`, honest limitations, build and run steps.
- **Demo script** with timestamps, and the clean-clone check.
- Commit the evidence the README cites: per-run JSON, reports and record caches under `results/`, after grepping them for
  any key pattern. (`.gitignore` previously swallowed `results/*/runs/`; fixed.)

## 3. Tier 2: depth that raises Meta-tooling and technical-depth scores
1. **Vision inside the hunting loop.** Today vision only cross-checks after a report. Let the agent request rendered frames
   while hunting. First smoke test whether Chat Completions accepts an image in a `tool` message; if not, attach the image
   as a user message right after the tool result.
2. **Counterfactual-checked explanations.** The model predicts a parameter change that should remove the violation
   ("raise the wall thickness to 0.3"); the engine tests it. This replaces the weak keyword check as evidence that an
   explanation is right, and uses no ground truth.
3. **Hypothesis ledger.** A `propose_hypothesis` / `update_hypothesis` tool so hypotheses are structured events the viewer can show.
4. **Campaign mode.** After one confirmed failure, keep hunting other rules under the remaining budget and rank the findings.
5. **Prompt-cache friendly prompts** (cached input is $0.15 vs $1.25 per 1M tokens; already ~80% of input in the first runs).

## 4. Tier 3: stretch, only if Tier 1 and the README are finished
- **Second domain**, to back the "any simulator" claim: a small control loop (thermostat or PID) with 3 to 4 seeded bugs,
  run without changing agent code. If it ships, say so; if not, the README says one domain only.
- **CI export:** write the minimal scenario as a JSON regression test plus a one-line `rc_replay` command.
- **Auto-repair:** the model reads the source and proposes a patch; the harness rebuilds and re-runs the shrunk repro and
  the suite. Separate mode, kept out of the black-box evaluation because it reads the code that contains the bug.
- Open-weight run on Muse Spark Open, only if Baseten or Modal credits arrive (decision date Nov 1).

## 6. UI/UX and sound design
Look: dark instrument-panel style, one accent colour, red only for violations; monospace for numbers; a short shockwave ring at
the violation step. Keyboard: space play/pause, left/right step, J/K previous/next violation, M mute. Respect
`prefers-reduced-motion`. Layout holds at 1280 px for screen capture.

Sound: synthesized with WebAudio (oscillators, noise bursts, envelopes), so there are no asset licences to worry about.
Every sound is triggered from the same event stream as the visuals, so live and recorded runs sound identical.

| Event | Sound |
|---|---|
| Ambient | very quiet low drone; pitch rises slightly with energy error |
| Tool call / result | soft tick (pitch per tool); rising blip for ok, flat for error |
| Hypothesis | short ping |
| Violation found | low sub hit plus dissonant stab and a brief noise glitch |
| Shrink | descending filtered sweep with ticks that accelerate as the scenario shrinks |
| Report accepted | resolved major arpeggio |
| Report rejected | short buzzer |
| Scoreboard | bars fill with a rising tick sequence |

Starts muted until the first click or key (browser autoplay rules); mute and volume in the top bar. macOS screen recording
often cannot capture system audio without a virtual audio device: test this on day 5, not on recording day.
